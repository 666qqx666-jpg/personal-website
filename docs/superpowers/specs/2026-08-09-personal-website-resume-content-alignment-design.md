## 1. 背景

完整版简历已经完成新一轮调整，两页 PDF 也已按投递篇幅压缩，但个人网站仍保留较早的项目口径。主要冲突包括：

- 网站下载的 `public/resume.pdf` 不是用户提供的最新两页 PDF。
- 网站仍以 `Personal Knowledge Harness` 和“个人稳定自用”描述 AI 实践，与完整版简历中的企业级叙事不一致。
- 网站没有把“企业产品交付 Agent Harness”的能力拆回需求发现、PRD、原型和报价等对应 Skill 模块。
- 销售线索项目仍使用“全域销售线索管理系统”和“前任建设多平台接入底座、本人后续承接”等旧口径，与完整版简历中的从 0 到 1 建设事实冲突。
- About 页、AI 列表、Skill Desk、网页版简历和项目详情页之间存在名称、职责、状态与结果口径漂移。

本轮不把两页 PDF 机械复制到网站，而是建立“事实统一、叙事分层”的内容体系。

## 2. 目标与成功标准

### 2.1 目标

1. 将用户提供的两页 PDF 原样接入网站主简历下载入口。
2. 以完整版简历为事实母稿，统一所有公共页面的项目名称、角色、时间、职责、状态、关键行动与结果数据。
3. 保留网站详情页比简历更完整的背景、产品判断、业务流程和方案取舍。
4. 将现有 `Personal Knowledge Harness` 升级为 `Enterprise Knowledge Harness｜企业知识与上下文平台`。
5. 不新增“企业产品交付 Agent Harness”详情页，而是把其能力和证据放入 Skill Desk 的对应模块。
6. 重点重写销售线索项目，并审计其他商业项目中可能存在的事实冲突。

### 2.2 成功标准

- `public/resume.pdf` 与用户提供的 PDF 字节一致，SHA-256 相同。
- 网站不再公开使用 `Personal Knowledge Harness`、“个人稳定自用”“尚未推广给团队”或“前任产品负责人建设多平台底座”等旧口径。
- About 页同时呈现企业产品交付 Agent Harness 和 Enterprise Knowledge Harness，且二者分别连接 Skill Desk 应用层和 Knowledge Harness 基础层。
- Skill Desk 能看出需求发现、PRD Writer、冷启动 Reviewer、原型、PRD 同步和报价交付之间的完整链路。
- 销售线索项目统一使用“全渠道销售线索管理系统”，明确从 0 到 1 建设七个平台接入及完整任务生命周期。
- 其他商业项目保留有效深度内容，同时与完整版简历的事实边界一致。
- Astro 构建、类型检查、内容断言、相关及全量 E2E 测试通过，关键页面无移动端横向溢出。

## 3. 内容真值与叙事层级

### 3.1 内容真值顺序

1. `docs/resume/完整版-简历.md`：项目事实母稿。
2. 用户提供的两页 PDF：压缩投递版，只决定网站下载文件，不反向删减网站内容。
3. 网站既有详情页：可提供更深的过程证据和产品取舍，但不得与事实母稿冲突。

本轮不修改完整版 Markdown、DOCX、其他简历版本或简历生成脚本。

### 3.2 叙事分层原则

- 简历回答“做了什么、负责什么、产生什么结果”。
- About 页回答“候选人的能力结构和代表项目是什么”。
- Skill Desk 回答“企业产品交付 Agent Harness 如何由多个工作包组成并运行”。
- Enterprise Knowledge Harness 详情页回答“企业知识怎样生产、治理、组装、发布和回滚，并向工作流提供最小充分上下文”。
- 商业项目详情页回答“复杂业务问题如何被建模、取舍和落地”。

## 4. 页面与模块设计

### 4.1 首页、导航与 Profile

- 将“个人 AI Agent 工作台”统一调整为企业 Agent 工作流与知识平台能力。
- 保留 AI 产品经理求职定位和复杂业务建模能力，不改变现有视觉结构。
- 导航中的主简历下载继续指向 `resume.pdf`，下载文件名保持 `钱麒祥-AI产品经理.pdf`。

### 4.2 About 页

AI 产品实践展示两张项目卡：

1. `企业产品交付 Agent Harness`
   - 角色：产品设计与架构负责人。
   - 时间：2026.04–至今。
   - 状态：内部复用｜持续完善工作包。
   - 摘要覆盖需求抽象、工作流架构、企业知识接入、质量门禁、PRD、原型和报价工作包。
   - 详情入口链接到 Skill Desk，不新增独立项目页面。
2. `Enterprise Knowledge Harness｜企业知识与上下文平台`
   - 角色：产品设计与架构负责人。
   - 时间和状态沿用完整版简历。
   - 详情入口继续使用 `/ai/knowledge-harness/`。

同时更新 AI 概览指标和职业摘要：

- 企业知识库与 PRD 写作、独立审查工作流覆盖产品部门所有同事，渗透率 100%。
- PRD 从写作到通过独立审查、达到可交付状态的周期由近 1 个月缩短至约 2 周。
- PRD 审查环节节省 50% 时长。
- 团队覆盖率和效率结果只归属于已经验证的企业知识库与 PRD Writer/Reviewer，不扩散到报价、原型、竞品分析或其他 Skill。

About 页的商业项目卡全部对照完整版简历校准名称、职责、状态和结果数据。

### 4.3 AI 列表页

- 旗舰项目名称改为 `Enterprise Knowledge Harness`。
- Hook 改为企业知识生产、权威治理、最小上下文组装和产品工作流接入，不再使用个人知识库叙事。
- Skill Desk 的说明调整为企业产品交付 Agent Harness 的应用层入口，同时保留个人阅读、复盘等非企业工作流的独立边界。

### 4.4 Enterprise Knowledge Harness 详情页

保留 `/ai/knowledge-harness/` URL 和现有 Deck 交互形式，重写内容结构：

1. 企业规范、历史项目经验和业务文档分散所造成的问题。
2. “企业知识库不是文档集合”的产品判断。
3. 原始材料、正式知识、企业能力包和 Agent 工作流的分层架构。
4. 材料快照、内容切分、证据片段、候选知识卡、人工裁决到正式知识的生产链路。
5. 领域索引、任务索引和项目记忆索引。
6. 按任务类型、项目范围和知识权威顺序组装最小充分上下文。
7. 相关性、权威性、时效性和上下文预算共同参与知识卡排序。
8. 弱相关、冲突、过期和缺失材料的降级或人工确认行为。
9. 灰度发布、版本校验和生产级回滚。
10. 接入 PRD Writer、独立 Reviewer 后的团队覆盖和结果证据。

旧页面中仅服务个人知识库叙事的标题、数字、阶段和结论不再保留。与企业方案仍一致的方法细节可以改写后复用。

### 4.5 Skill Desk：企业产品交付 Agent Harness 应用层

Skill Desk 首页增加一条清晰的企业产品交付链：

`需求发现 → PRD Writer → 冷启动 Reviewer → 原型生成 → PRD 同步 → 结构化报价`

Enterprise Knowledge Harness 通过企业规则、历史经验和项目记忆为这条链提供最小充分上下文。

#### 需求发现

- 保留需求来源、角色影响、证据缺口和 V0 收敛。
- 增加存量项目依赖识别：涉及历史系统时，先核对历史代码、文档和项目决策，再进入方案设计和 PRD。
- 明确需求发现是 Agent Harness 的上游门控，不自动越过边界生成完整方案。

#### PRD Skill

- 统一使用 PRD Writer 与冷启动 Reviewer 两个隔离工作流。
- Reviewer 不继承 Writer 对话中的隐含假设。
- 存在关键问题时阻止文档进入后续原型、报价或实施交付。
- 将产品部门覆盖率、渗透率 100%、周期由近 1 个月缩短至约 2 周、审查节省 50% 时长放在该模块的结果区。
- 删除“当前只是个人 workflow、团队复用仍是潜力”等过时状态。

#### 原型设计工作流

- 从“等待实战验证”调整为“已完成规划和验证、持续完善工作包”。
- 继续不新增独立详情页。
- 在 Skill Desk 首页说明：基于已经封口的 PRD 和真实页面基线生成高保真原型，并在原型结束后通过 PRD 同步门回写偏差和新增规则。
- 不编造团队采用人数或效率比例。

#### 报价工作流

- 从“个人报价生成 workflow／团队复用潜力”调整为已进入企业交付链的结构化报价工作包。
- 输入以需求蓝图、功能边界和交付范围为准。
- 输出继续保留客户可读模块、角色工时、报价预览和飞书报价单。
- 强调减少产品经理、项目经理和销售的人工拆分与反复核对，但不新增未经验证的效率数字。

#### memory-loader

- 作为 Enterprise Knowledge Harness 向各工作流提供企业规则、经验和项目记忆的接口。
- 删除所有 `Personal Knowledge Harness` 旧称。
- 强调任务类型、项目范围、知识权威性、时效性和上下文预算，而不是加载更多内容。

#### 其他 Skill

- 竞品分析、阅读、复盘和其他个人工作流继续保留。
- 不把所有 Skill 包装成企业团队已经采用。
- Skill Desk 底部关系明确为：Skill Desk 是应用层，Enterprise Knowledge Harness 是知识与上下文基础层。

### 4.6 全渠道销售线索管理系统

- 全站名称统一为 `全渠道销售线索管理系统`。
- 角色、时间和状态与完整版简历一致。
- 本人职责改为从 0 到 1 负责整套系统建设，覆盖抖音、快手、美团、小红书、高德、微信和支付宝七个平台。
- 保留并强化以下网站深度内容：
  - 统一平台线索来源、门店和状态口径。
  - 资格筛选、候选门店排序和智能分发。
  - 场景保护期、阶段扩圈、公海池认领和超时回收。
  - 品牌治理下的门店采购模式，以及付费认领对既有生命周期的兼容。
- 删除以下旧口径：
  - 早期多平台接入底座由前任产品负责人建设。
  - 本人只从智能分发、任务和公海池开始主导。
  - 清洗层已排期、付费认领仍在规划中的旧阶段描述。
- 结果证据统一为约 10 个付费品牌、约 15,000 家上线门店、累计约 102.6 万条线索、当前月处理约 10 万至 30 万条，以及匿名客户核销率由不足 49.4% 提升至 61.7%。

详情页保留现有流程图和业务取舍表达，不照抄简历段落。

### 4.7 其他商业项目

逐页审计多业务线企业权限体系、集团经营数据分析体系、多平台会员运营体系和智慧停车 2.0：

- 名称、角色、时间、职责、状态和结果数据必须与完整版简历一致。
- 与母稿不冲突的复杂业务图解、边界规则、技术债说明和产品取舍继续保留。
- 若详情页中的旧数据与母稿冲突，以母稿为准。
- 若某一细节只是因两页 PDF 篇幅压缩而未出现，但与母稿和现有项目证据一致，则保留。

### 4.8 网页版简历

## 5. 组件与数据流

### 5.1 公共事实数据

`src/data/resume/facts.ts` 承担 About 页和网页版简历的公共项目事实，包含名称、角色、时间、状态、职责、关键行动与结果。

About 项目视图允许两类详情入口：

- 真实项目详情页，例如 Enterprise Knowledge Harness 和商业项目。
- 能力集合入口，例如企业产品交付 Agent Harness 指向 Skill Desk。

不创建空页面，也不使用误导性链接。

### 5.2 页面叙事数据

- Skill Desk 继续使用 `src/data/skillDesk.ts` 维护各工作流的过程叙事。
- 商业详情页继续保留各自 Astro 页面与动效脚本。
- 公共事实通过测试与完整版简历锁定，页面过程叙事由人工审计保持一致。

### 5.3 PDF 数据流

用户 PDF 直接复制为 `public/resume.pdf`。不经过重排、压缩或重新导出。完成后比较两个文件的 SHA-256，并继续检查网站下载链接和文件名。

## 6. 边界与异常处理

- 不修改 `docs/resume/完整版-简历.md`、DOCX、B2B / SaaS PDF、简历生成脚本和现有用户未提交内容。
- 不新增企业产品交付 Agent Harness 独立详情页。
- 不重新设计网站整体视觉系统。
- 不将目标态、规划态或个人验证结果包装成团队量化成果。
- 某项详情缺少足够证据时，删除、弱化或标明边界；不得为保持页面丰满而编造结果。
- 旧链接 `/ai/knowledge-harness/` 必须继续可访问。
- 静态页面不存在运行时数据请求失败；主要异常是内容漂移、链接失效、类型不一致、构建失败和移动端溢出，均通过构建和自动化测试拦截。
