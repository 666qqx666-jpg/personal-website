# 线上个人网站增量视觉演进设计

## 1. 设计摘要

本轮以当前线上站点 `https://qqx.life/` 为唯一视觉与信息架构基线，不沿用 2026-08-13 本地“证据评审墙”重构的统一案例外壳。

改造目标不是再次重做全站，而是把线上案例详情页已经存在的深度提前透露给首页和项目索引，并在 Enterprise Knowledge Harness 的关键转折处补足真实结构图、验证报告和产品决策之间的图文关系。

本轮只包含三个增量：

1. 首页在现有 Hero 之后增加非对称的“精选工作”区域。
2. 项目索引只替换销售线索与智慧停车两张抽象封面。
3. Enterprise Knowledge Harness 保留线上八章 Deck，只增强 V2、评测与 V1.5 的视觉证据。

现有导航、紫蓝品牌基调、案例独立舞台感、完整问题演进和其他页面均不重构。

### 1.1 文档优先级

当本设计与以下旧设计发生冲突时，以本设计为本轮网站视觉改造依据：

- `2026-08-11-evidence-led-systems-portfolio-redesign-design.md`。
- `2026-08-13-product-review-wall-portfolio-redesign-design.md`。

旧文档仍可提供事实来源和历史决策，但不能据此恢复统一证据外壳、朱红评审墙或全站重构范围。Knowledge Harness 的稳定产品事实继续以冻结报告、当前检查点和 `2026-08-10-enterprise-knowledge-harness-desk-narrative-design.md` 中未被本设计改写的部分为准。

## 2. 背景与问题判断

### 2.1 线上版本值得保留的部分

- 紫蓝渐变、网格背景和大字号标题已经形成可识别的个人品牌气质。
- 销售线索、智慧停车与 Knowledge Harness 采用独立 Deck，能保留案例各自的问题、失败尝试、机制和结果。
- 全屏章节、底部时间线与左右图文结构适合展示复杂系统的判断过程。
- 深层案例的内容密度已经明显高于普通简历，不需要重新压缩为统一摘要。

### 2.2 线上版本需要增量解决的问题

- 首页首屏之后缺少代表作品预览，访客在点击前看不到案例深度。
- 项目索引使用抽象渐变封面，无法提前证明项目真实性。
- Knowledge Harness 当前 V2 与评测图形过于简化，未完整呈现两轮返修、报告证据与“不切流”决策之间的因果关系。
- 真实截图、验证报告和结构图尚未形成稳定的图文分工。

### 2.3 上一轮失败中不再沿用的做法

- 不把所有案例迁入同一种卡片或统一案例外壳。
- 不把案例压成“问题 / 负责人 / 机制 / 边界”的说明书。
- 不展示“哪些不能夸大”“结果必须跟随边界”等面向编辑者的元文案。
- 不用跨项目数字拼成首页指标墙。
- 不把测试通过、结构完整或卡片数量当作审美完成的替代指标。
- 不用生成式后台界面、虚构数字或抽象渐变替代真实证据。

## 3. 目标、受众与成功标准

### 3.1 主要受众

- 企业 AI 产品经理岗位的招聘决策者。
- 产品负责人、产品同行与关注 AI 工作系统的人。
- 次要受众为希望继续了解实现细节的技术访客。

### 3.2 页面需要建立的职业心智

访客应先看见：

> 钱麒祥能够把 AI、企业知识和产品交付流程连接成可运行、可验证的工作系统，同时具备复杂 B2B 业务系统经验。

复杂业务案例用于证明业务建模与长期交付基础；Agent Harness 与 Knowledge Harness 是当前职业方向的主线。

### 3.3 成功标准

- 首页第一屏之后即可识别两类旗舰 AI 工作与两类复杂业务证据。
- 首页的 AI 工作系统在视觉层级上明显高于业务案例，但两条经验线不割裂。
- 首页不出现门店、线索、PRD 等彼此无关的数字拼贴。
- 项目索引至少有两个案例通过真实脱敏视觉建立可信度。
- Knowledge Harness 的核心转折能用一屏回答：V2 做了什么、两轮验证发现了什么、为什么没有切流。
- 所有公开数字均能回到冻结报告；未完成的三版本盲测不产生公开结论。
- 桌面、移动端、明暗主题、键盘导航和底部章节导航继续可用。

## 4. 设计原则

### 4.1 保留公共外壳，保留案例个性

全站共享导航、色彩变量、字体、基础间距与无障碍规则；案例内容仍使用各自的 Deck、视觉节奏和图形语言，不再追求全站卡片同构。

### 4.2 把深度提前，不把深度压平

首页和索引只提供案例“预告片”：真实视觉、一个关键判断和一种系统机制。完整叙事仍留在案例详情页。

### 4.3 图像承担证明，文字承担判断

- 真实截图证明系统与材料存在。
- 结构图解释机制和关系。
- 报告切片证明验证过程与状态。
- 一级文案只解释当时的问题、判断和决策，不重复图中的节点清单。

### 4.4 先做两个可验收样板

本轮只验收一个首页新增区域和一个 Knowledge Harness 核心转折屏。未通过人工视觉验收前，不扩散到其他案例。

## 5. 首页增量设计

### 5.1 保留项

- 现有导航结构与导航文案。
- 现有姓名、求职方向、职业转向和简介。
- 紫蓝渐变、浅色网格、白色导航与深浅主题。
- 现有“作品与思考”入口，继续放在新增区域之后。

### 5.2 Hero 调整

Hero 只缩短垂直高度，使新增内容能在常见桌面视口中露出入口；不改变其中心构图，不新增大型 CTA，不引入红黑配色。

Hero 的信息优先级为：

1. 钱麒祥。
2. 企业 AI 产品经理。
3. 把 AI 嵌入真实工作、构建可复用产品与系统的职业主张。

### 5.3 “精选工作”结构

新增区域采用非对称编辑式布局，不使用四张等宽卡片。

#### 第一层：企业 AI 工作系统

左侧约三分之二为 Enterprise Knowledge Harness 主卡：

- 使用多层架构局部作为主要视觉。
- 同屏露出一份脱敏验证材料切片。
- 文案只回答“让企业经验成为 Agent 可复用的判断力”。
- 不在首页展开版本比较和验证数字。

右侧约三分之一为 Enterprise Product Delivery Agent Harness 辅助卡：

- 使用真实工作流或任务交付切片。
- 表达需求发现、PRD、独立审查和人工决策如何形成交付链。
- 不把 Skill Desk 的技能数量作为主要视觉。

#### 第二层：复杂业务系统

销售线索与智慧停车使用两条较矮的横向案例切片：

- 销售线索使用真实系统截图或责任闭环图。
- 智慧停车使用真实产品截图或 1.0 到 2.0 的系统演进图。
- 每个切片只有项目名、一个关键问题和一处视觉证据。
- 不在首页并列展示门店数、线索量、账单量等异质指标。

### 5.4 视觉规则

- 紫色承担氛围与活动状态，蓝色和青色承担稳定系统信息。
- 卡片主体保持白色或中性灰，不使用整块高饱和渐变。
- 不使用玻璃拟态、赛博 3D、漂浮胶带、装饰箭头或模板化设备框。
- 不通过大量圆角胶囊制造层级。
- 桌面为非对称布局，移动端按 Knowledge Harness、Agent Harness、销售线索、智慧停车顺序单列。

## 6. 项目索引最小改造

### 6.1 保留项

- 线上项目索引的页面结构、卡片顺序、标题、简介、标签和链接。
- 五个商业案例仍然共同存在，不改变项目范围。

### 6.2 本轮只替换两个封面

#### 销售线索管理

- 用脱敏后台列表、分配界面或责任闭环图替换抽象渐变。
- 优先选择能说明“线索如何进入、分配并被门店承接”的画面。
- 不使用生成式 CRM 仪表盘。

#### 智慧停车系统

- 用脱敏产品界面、支付生命周期或 1.0 到 2.0 演进图替换抽象渐变。
- 不使用赛博城市、停车数字孪生或与真实项目无关的 3D 图。

其余会员营销、集团经营分析与企业权限三个封面本轮不动，待各自具备准确的脱敏材料后再单独评审。

### 6.3 资产规则

- 原始截图先在项目外完成脱敏，再进入公开资产目录。
- 封面使用固定比例裁切并保留关键交互上下文，不只截取无意义局部。
- 不在浏览器端加载原始高清敏感图后再用 CSS 遮挡。
- 缺失资产时构建应失败或显式回退到原渐变，不显示破图。

## 7. Enterprise Knowledge Harness 增量设计

### 7.1 页面骨架

保留线上八章 Deck 与底部导航：

1. 封面。
2. 问题。
3. 知识产生。
4. V1。
5. V2。
6. 评测。
7. V1.5。
8. 结果。

封面、问题、知识产生、V1 和结果优先复用线上设计，不因本轮视觉增强重新改写。

### 7.2 第 05 章：V2 假设

第 05 章只负责建立实验动机：随着角色、材料和跨项目知识增加，V1 的文件数量控制不足以稳定上下文，因此需要验证更强的检索、排序、质量门和可观察性。

该章不再承担完整评测结果，只用简化的分层线索把访客带入下一章，避免与第 06 章重复。

### 7.3 第 06 章：正式视觉方向

第 06 章采用已经确认的“V2 架构 + 两轮验证 + 不切流决策”一屏构图。

#### 左侧叙事区

- 章节标题：工程能力更完整，为什么仍然没有切流？
- 一句主判断：V2 把查找、排序、冲突处理与组装拆成可观察的分层链路，但系统更复杂，不等于工作价值更高。
- 两轮验证沿垂直时间线排列，先显示结果变化，再显示 `activation=false`。

#### 右侧证据画布

上半区为多层架构：

```text
Task & Profile
→ Query Planning
→ Retrieval & Ranking
→ Quality Gate & Conflict Handling
→ Context-Pack & RetrievalTrace
```

图中保留 Query Planner、RoleRetriever、RRF、Reranker、Selector、Composer 与 Renderer 等技术证据，但它们不进入左侧一级文案。

下半区为两份报告切片与决策门：

```text
第一次验证
V1 16/20 → V2 8/20
上下文精度 31.9%
必需角色覆盖 1/20

        ↓ 返修

第二次验证
V1 18/20 → V2 16/20
上下文相关性 87.2%
必需角色覆盖 19/20
6 个完成输出回归

        ↓

activation=false
→ V2 保持 Shadow
→ 有效机制收敛进 V1.5
```

报告使用代码生成的脱敏报告外观或真实材料切片，不直接发布视觉伴侣 PNG，也不把报告做成普通指标卡。

### 7.4 第 07 章：V1.5 收敛与两轮验证

V1.5 章节继续说明：它不是 V2 失败后的简单回退，而是保留 V1 的有效性并吸收 V2 的 Profile、两阶段组装、RetrievalTrace 和可替换检索接口。

结构图只展示 V1.5 自身运行方式，不制作 V1、V1.5、V2 三列横向对照：

```text
Task
→ Profile 判断任务、角色与知识边界
→ 第一阶段：查找候选
→ 第二阶段：审查、冲突处理与组装
→ Context-Pack
```

两轮已冻结检索验证作为章节下部证据：

- 第一次：20 题中 11 题通过，9 题失败；失败来自候选和覆盖判断，不是运行器故障。
- 第二次：20/20 纯检索契约通过、0 失败；整体 Gate 仍为 `incomplete`，因为模型答案与人工盲评尚未形成最终结论。

不得把第二轮 20/20 写成 V1.5 已经赢得三版本比较或具备生产切流资格。

### 7.5 三版本盲测的公开策略

V1、V1.5、V2 三版本同题盲测进行期间：

- 公开页面不显示进度、中间排名、中间分数或“正在盲测”占位文案。
- 首页与项目索引不引用盲测结果。
- 当前八章导航不增加空章节。
- 数据与章节结构允许未来在 V1.5 和结果之间插入可选的“三版本决策”模块；该模块缺失时不渲染任何 DOM 或导航项。

盲测完成、揭盲和结论复核后再决定内容形态：

- 有明确决策时，展示选择与原因。
- 各版本存在任务类型差异时，展示适用条件而不是宣布单一赢家。
- V1.5 表现不佳时，作为失败证据保留并说明路线如何改变。

## 9. 组件边界

以下是实现计划应遵守的职责边界，不要求现在创建组件：

- `SelectedWork`：只负责首页精选工作布局。
- `WorkPreview`：负责单个真实案例预览及其响应式裁切。
- `V2Architecture`：只负责五层系统结构与可访问语义。
- `ValidationReportExcerpt`：负责单轮冻结报告的脱敏呈现。
- `ValidationDecisionFlow`：负责两轮验证到不切流决策的因果连接。
- `V15Convergence`：只负责 V1.5 两阶段运行结构。
- 可选三版本模块拥有独立数据契约，不与现有四轮验证组件混用。

结构图应由 HTML/CSS 或现有 SVG 组件生成，不把视觉伴侣栅格图当作正式页面内容。

## 10. 响应式与无障碍

- 桌面端第 06 章采用左叙事、右证据画布。
- 移动端顺序固定为标题与判断、V2 架构、第一次报告、第二次报告、决策门。
- 移动端不通过横向滚动保留桌面画布；架构节点改为纵向层级。
- 报告切片必须有等价文本，不能只依赖图片 OCR。
- stable、shadow、fail 与 gate 状态必须同时使用文字或形状，不只依赖颜色。
- 底部时间线、主题切换、返回链接与所有可交互元素继续满足键盘访问和可见焦点要求。

## 11. 验证与验收

### 11.1 事实验收

- 四轮验证数字与冻结报告一致。
- V2 的公开状态仍为 Shadow，未进入生产切流。
- V1.5 20/20 只描述纯检索契约，整体仍为 incomplete。
- 页面不存在三版本赢家、正式切流或未完成盲测分数。

### 11.2 视觉验收

- 先人工验收首页新增区域和 Knowledge Harness 第 06 章桌面、移动两种视口。
- 首页第一眼先看到 AI 旗舰，再看到复杂业务底座。
- 第 06 章一屏能看清架构、两份报告与决策门，且右侧不是普通数据仪表盘。
- 销售线索与智慧停车封面使用真实脱敏材料，其他三个封面保持原状。
- 明暗主题下文字、虚线、报告纸张与状态色均清晰。

### 11.3 回归验收

- 现有公共 URL、导航顺序、主题切换和章节 Hash 不回归。
- 首页原有“作品与思考”仍可访问。
- 其他商业案例和 Skill Desk 不发生结构变化。
- 桌面和移动端无横向溢出、布局跳动或破图。
- 图片具有固定尺寸、延迟加载策略与合理的公开格式，不显著增加首屏加载成本。

## 12. 实施边界与顺序

本设计不授权立即实施。用户书面确认本 Spec 后，下一步只创建实施计划。

实施计划应拆为三个可独立验收的增量：

1. 恢复并冻结线上视觉基线，完成首页精选工作样板。
2. 完成 Knowledge Harness 第 05–07 章的证据增强，优先验收第 06 章。
3. 替换销售线索与智慧停车索引封面并完成定向回归。

每个增量失败时均可撤回到线上基线；不得以完成第一阶段为由自动扩散到其他页面。
